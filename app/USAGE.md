# DSH Pair · 使用说明

> 这是给**用户**看的（不是开发文档）。开发向的说明在 `README.md`，协作规约在 `%REPO%\BOARD.md`。

## 这是什么

一个窗口里**同时跟两个 AI 助手说话**的程序：左边一栏是**Desktop**（DSH Desktop，工作区 `%WORKSPACE_B%`），
右边一栏是**Harness**（DeepSeek Harness，工作区 `%WORKSPACE_A%`）。

界面样子见 `docs\ui-names.png`。

你能做的事：

| 想做的事 | 怎么做 |
| --- | --- |
| 只跟其中一个说话 | 点下面的 `只发 Desktop` / `只发 Harness` |
| 同时跟两个说 | 点 `两边都发`（默认），一句话两边都收到 |
| 看谁在忙 | 栏头状态点：🟢`空闲` / 🟠`正在跑`（会呼吸）/ 🔴`离线` |
| 切换历史会话 | 栏头的会话下拉（按最近活跃排序；📱 = 你在**手机端**聊过的会话） |
| 打断正在跑的一轮 | 栏头 `打断` |
| 换深色/浅色 | 右上角 `主题` 按钮：跟随系统 → 浅色 → 深色（会记住选择） |
| 发多行文字 | `Shift+Enter` 换行，`Enter` 发送 |

## 怎么开始

1. **双击桌面的 `DSH Pair`**（或 `%REPO%\app\start-app.cmd`）。
   它会开一个独立窗口（没有标签页和地址栏），后端没在跑时自动拉起来，**并且自动重启**（见下）。
2. 前提：
   - 装了 **Node.js 18+**；
   - 两台 DSH 各自开着（你的 DSH Desktop，和Harness的 Harness）—— 哪一边没开，那一边就会显示 **离线**，
     等它起来会自动恢复，不用重启程序。
3. 想放桌面图标：跑一次 `%REPO%\app\make-desktop-shortcut.cmd`。

> 浏览器标签页版入口是 `start.cmd`（功能相同，方便按 F12 看调试信息）。

## 出问题怎么办

### ① 顶栏出现 `⚠ 后端已停止`

意思：程序的后台进程（负责跟两个 DSH 说话的那部分）**没了**。这时页面本身还能看见，但发消息不会成功。

怎么办：**直接双击桌面的 `DSH Pair` 再开一次**即可（已经在跑就只会开窗口）。
正常情况下不用你管 —— 后端有**看门狗**守着：它一旦异常退出，会在 2 秒~60 秒内自动重启
（短时间内连续失败 6 次会放弃并停止重试，避免一直空转）。

想知道**为什么**挂的：看日志（下一条）。

### ② 想知道发生了什么 → 看日志

| 文件 | 内容 |
| --- | --- |
| `%REPO%\app\logs\server-<端口>.log` | 启动信息、两侧连接情况、4xx/5xx 报错、崩溃栈、**每 5 分钟一次心跳** |
| `%REPO%\app\logs\watchdog-<端口>.log` | 看门狗的决策：什么时候发现后端没了、第几次重启、为什么放弃 |

日志里**不会写任何密钥/令牌**（有自动化测试盯着这一条）。

如果日志最后一行是 `exited unexpectedly (code=4294967295)` —— 那是被外部**强制结束**的签名
（不是程序自己崩的），这种情况看门狗会立刻把它拉回来。

### ③ 启动器窗口一闪就没了 / 说"the server did not come up"

`start.cmd` 探活失败时会把**日志最后 15 行**直接打在窗口里，并保留窗口（`pause`）。
按照它显示的报错处理；最常见的是**端口被占用**（提示里会告诉你换端口或用已存在的实例）。

### ④ 某一栏一直"离线"

- 那一侧的 DSH 没开 → 开起来即可；
- 那一侧**刚重启过**（端口和令牌会变）→ 等几秒，程序会重新读取它的端点文件自动接上；
- 一直不行 → 看那一栏下方的红字，里面写了连不上的地址和原因。

### ⑤ 消息发出去了，对方没反应

- 状态是 🟠`正在跑` → 它在干活，等它跑完（长任务可能几分钟）；
- 出现黄色提示 `⚠ 这一轮没有正常结束（blocked）` → 是**权限预设**问题：
  那一侧的会话被设成了"需要审批"，而程序里没有审批入口。让那一侧的会话改用
  `danger-full-access` 预设（或在Harness的插件里给新会话默认该预设）。

## 怎么停止 / 清理

- **停止**：双击 `%REPO%\app\stop.cmd`。它会**先停看门狗再停后端**，只动本目录的实例。
  ⚠️ 不要用 `taskkill /IM node.exe`（会杀掉机器上所有 node 程序，我们踩过这个坑）。
- 程序不写注册表、不装服务、不改系统设置。所有文件都在 `%REPO%\`：
  - `app\` 程序本体；`app\logs\` 日志（可随时删）；`peer\` 桥客户端；`docs\` 截图；`tools\` 自查工具。
- 想彻底清干净：停掉进程，删掉 `%REPO%\app\logs\` 和 `app\*.pid` 即可（其余是源码/文档）。

## 关于隐私和安全

- 程序**只监听本机**（`127.0.0.1`），不对局域网开放；跟两个 DSH 的通信也全在本机。
- 每个请求都要带一个**每次启动随机生成**的令牌（注入在页面里），
  以免别的网页偷偷驱动你的两个助手；还会拒绝非本机来源的跨站请求。
- 日志、截图、交付文档里**不含** API key / 令牌；共享目录有自动化扫描工具
  （`tools\scan-secrets.js`）可以随时自查，它只输出"前 6 位 + 长度"。
- 这个程序会**真的驱动两个 agent**（能读写文件、执行命令，等同于你直接跟他们说话），
  所以别在别人的电脑上跑，也别把它的端口暴露出去。

## 已知限制

- 目前是"独立窗口（Edge app 模式）"，需要机器上有 Edge；找不到会退回默认浏览器。
  **真·免依赖 exe 正在做**（看板 B1，Harness负责），做完会替换入口。
- 只轮询（1 秒一次），没有做"实时事件流"；对聊天够用。
- 不做附件、审批、问答转发；多标签页之间互不同步（各自轮询，互不干扰）。
